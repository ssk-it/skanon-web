# Glossary

The domain vocabulary, from the French of the format to the English of the code. The format term is the one SSK Canon files and the interface write, in French; the code term is the one TypeScript and Vue identifiers use ([conventions.md](conventions.md)). An English term has only one meaning in the code, and a format term only one English name.

Where a value is still written in French in the code, it is a value of the format, kept as files store it ([conventions.md](conventions.md#what-stays-in-french)).

## The specification and its content

| Format term                                        | Code term                                  | Definition                                                                                                                                                                                                                                                                                                   |
| -------------------------------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| référentiel                                        | `specification`                            | The living specification of a product — its domains, features, business rules and architecture records — as the default branch of its scoping repo holds it. _Repository_ is the Git repo, _catalog_ suggests a product list, _baseline_ a version; _specification_ is what rules and domains together form. |
| domaine                                            | `domain`                                   | A business area that groups features.                                                                                                                                                                                                                                                                        |
| fonctionnalité                                     | `feature`                                  | A user-facing capability, attached to one or more domains.                                                                                                                                                                                                                                                   |
| règle (de gestion)                                 | `rule`                                     | A business rule: one stable identifier (`RG-…`) and a statement saying what the product does.                                                                                                                                                                                                                |
| énoncé                                             | `statement`                                | The Markdown text of a rule, an architecture decision or an architecture document.                                                                                                                                                                                                                           |
| statut d'une règle : actif / abrogé                | `RuleStatus`: active / repealed            | Whether a rule still applies; values stay `"actif"` / `"abroge"`.                                                                                                                                                                                                                                            |
| créé par / modifié par                             | `createdBy` / `modifiedBy`                 | Indexes derived from history by propagation, naming the scopings that created or modified an entry; never a source of truth (`INV-2`). The YAML keys stay `cree_par` / `modifie_par`.                                                                                                                        |
| décision d'architecture                            | `ArchitectureDecision`                     | An ADR (`ADR-…`): why the system is built the way it is; same shape as a rule, not attached to any feature.                                                                                                                                                                                                  |
| document d'architecture                            | `ArchitectureDocument`                     | A component, flow or context description under `architecture/`.                                                                                                                                                                                                                                              |
| nature d'un document : composant / flux / contexte | `DocumentKind`: component / flow / context | What an architecture document describes; values stay `"composant"`, `"flux"`, `"contexte"`.                                                                                                                                                                                                                  |
| nature (en général)                                | `kind`                                     | The category of a thing (impact target, document, search result). _Nature_ is English too, but `kind` is the idiomatic TypeScript discriminant name.                                                                                                                                                         |
| préfixe de projet                                  | `prefix`                                   | The text shown in front of identifiers, as the project declares it.                                                                                                                                                                                                                                          |

## The scoping

| Format term                                                       | Code term                                                 | Definition                                                                                                                                                                                                                |
| ----------------------------------------------------------------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| cadrage                                                           | `scoping`                                                 | A dated unit of change (`2026-047`) stating what is to be done, why, and which rules it creates, modifies, repeals or touches. _Proposal_ or _RFC_ would hide that a scoping also carries its own decisions and delivery. |
| statut d'un cadrage : brouillon / en relecture / validée / livrée | `ScopingStatus`: draft / in review / approved / delivered | Derived from the repo state (branch, pull request, review), never declared; values stay `"brouillon"`, `"en_relecture"`, `"validee"`, `"livree"`.                                                                         |
| bascule de statut                                                 | status toggle (`STATUS_TOGGLES`)                          | A status change the application can make itself — draft ↔ ready for review.                                                                                                                                               |
| objectif                                                          | `goal`                                                    | The "Objectif" section: why the scoping exists.                                                                                                                                                                           |
| parcours (utilisateur)                                            | `journey`                                                 | The "Parcours utilisateur" section: what the user goes through.                                                                                                                                                           |
| impact                                                            | `impact`                                                  | A line of a scoping naming a target (rule, ADR or architecture document) and an operation on it.                                                                                                                          |
| cible d'un impact                                                 | `target` (`TargetKind`)                                   | What an impact points at; the values stay `regle`, `adr`, `architecture`.                                                                                                                                                 |
| opération : crée / modifie / abroge / touche                      | `ImpactOperation`: create / modify / repeal / touch       | What the impact does to its target; values stay `"cree"`, `"modifie"`, `"abroge"`, `"touche"`.                                                                                                                            |
| décision (d'un cadrage)                                           | `decision`                                                | A question settled inside a scoping, with its options.                                                                                                                                                                    |
| option retenue                                                    | `chosenOption` (`Option.chosen`)                          | The option a decision settled on; the frontmatter key stays `option_retenue`.                                                                                                                                             |
| statut d'une décision : ouverte / retenue / annulée               | `DecisionStatus`: open / chosen / cancelled               | Values stay `"ouverte"`, `"retenue"`, `"annulee"`.                                                                                                                                                                        |
| pièce jointe                                                      | `attachment`                                              | A file attached to a scoping, listed with its SHA-256 in `attachments.md` (`INV-3`).                                                                                                                                      |
| divers                                                            | `misc` (`MiscSection`)                                    | Level-2 sections of a scoping the template does not name; kept and shown under "Divers".                                                                                                                                  |
| provenance                                                        | `provenance` (`ScopingProvenance`)                        | Where an undelivered scoping is read from: its branch, its pull request, its review state.                                                                                                                                |
| branche survivante                                                | stale branch (`staleBranches`)                            | A branch still carrying a scoping that has already been delivered. _Stale_ is git's own word for a branch left behind; _surviving_ would read as a positive.                                                              |
| relecture                                                         | `review` (`ReviewDecision`)                               | The pull-request review that turns a scoping from "in review" into "approved".                                                                                                                                            |
| propagation                                                       | `propagation`                                             | The post-delivery step that writes the derived indexes (`cree_par`, `modifie_par`) into the specification.                                                                                                                |
| rédaction                                                         | `authoring` (`AuthoringService`)                          | Creating and editing scopings from the application.                                                                                                                                                                       |
| rédacteur                                                         | `author`                                                  | A person who writes scopings. Same English word as a commit author: in this product they are the same person.                                                                                                             |
| piste                                                             | roadmap item (`RoadmapItemsService`, `RoadmapItemIssue`)  | Something envisaged for the product, carried by a GitHub issue labelled `piste` and placed on a horizon (now / next / later). _Lead_ would read as a sales or a person term.                                              |
| horizon / jalon                                                   | `horizon` / `milestone`                                   | When an idea is envisaged; the horizon is read from the issue's milestone.                                                                                                                                                |
| lien externe, tag de lien                                         | `ExternalLink`, tag (`normalizeTag`)                      | A link from a scoping to an outside resource (Trello card, issue, mock-up…), typed by a tag the project declares.                                                                                                         |

## Repos

| Format term                        | Code term                                             | Definition                                                                                                                                   |
| ---------------------------------- | ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| dépôt (Git)                        | `repo`                                                | A Git repository on the platform. _Repository_ alone is kept for the GitHub API's own fields.                                                |
| référence de dépôt                 | `RepoRef` (variables: `repoRef`)                      | Owner, name and optional ref of a repo. A variable of this type is `repoRef`, never `repo`, so that `repo.repo` cannot happen.               |
| dépôt de projet / dépôt de cadrage | scoping repo (`isScopingRepo`)                        | The repo that holds a project's specification and scopings, recognised by its `ssk-canon.yml`. The two French names designate the same repo. |
| dépôt cadré                        | `framed` (`KnownRepo.framed`)                         | Said of a repo that is a scoping repo.                                                                                                       |
| dépôt de code                      | code repo (`CodeRepo`, `codeRepos`)                   | A repo that implements the project, declared under `depots_code` in `ssk-canon.yml`.                                                         |
| identité (d'un projet), symbole    | project identity (`ProjectIdentityService`), `symbol` | The project's symbol images under `identite/`, chosen by background variant.                                                                 |
| empreinte                          | `fingerprint`                                         | A Git object SHA used as a content key; never "hash", which is a URL fragment in the router.                                                 |
| arborescence                       | `tree`                                                | The Git tree of a ref.                                                                                                                       |

## Access, tokens, machine

| Format term                                               | Code term                                    | Definition                                                                                                                              |
| --------------------------------------------------------- | -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| jeton                                                     | `token`                                      | A GitHub access token (`INV-8`). The injection-container key is `ProviderToken`, never `token`.                                         |
| portée (d'un jeton)                                       | `scope` (`ScopedToken`, `byScope`)           | What a token applies to: an organisation, or one repo.                                                                                  |
| mode d'accès : jeton personnel / identité tierce / relais | `AccessMode`                                 | How authors obtain access; values stay `"jeton_personnel"`, `"identite_tierce"`, `"relais"`.                                            |
| identité tierce, émetteur, échange                        | third-party identity, `issuer`, `exchange`   | Sign-in with an outside identity provider, its issuer URL, and the component that trades a verified identity for repo access (`INV-5`). |
| protection du jeton : proposée / exigée                   | `TokenProtection`                            | Whether a project offers or requires the passkey; values stay `"proposee"` / `"exigee"`.                                                |
| coffre                                                    | `vault` (`TokenVault`)                       | Where the target keeps tokens: the system keychain on desktop, local storage on the web.                                                |
| scellement, sceller, scellé                               | `sealing`, `seal`, `sealed` (`TokenSealing`) | Encrypting stored tokens under a key a passkey yields; _unlock_ opens them for the page.                                                |
| passkey                                                   | `passkey`                                    | A WebAuthn credential whose PRF output derives the sealing key.                                                                         |
| chiffreur                                                 | `cipher` (`Cipher`)                          | The object that seals and opens private contents with the passkey key.                                                                  |

## Application architecture

| Format term                        | Code term                                             | Definition                                                                                                                |
| ---------------------------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| plateforme                         | `platform` (`Platform`)                               | The set of system adapters the shell runs on, chosen at startup.                                                          |
| cible : bureau / web               | `target`: desktop / web                               | Which deliverable is running; values stay `"bureau"` / `"web"`.                                                           |
| port                               | `port`                                                | An interface the core declares towards the system (vault, sealing, opener, link receiver, version announcer).             |
| adaptateur                         | `adapter`                                             | One implementation of a port for one system, in one module.                                                               |
| extension                          | `extension`                                           | What a deliverable adds to the shared interface without the shared code knowing it (`INV-10`).                            |
| point d'extension                  | extension point                                       | A named place of the interface that receives contributions (toolbar actions, banners, help phrases, legal notice).        |
| apport                             | `contribution`                                        | One item given to an extension point.                                                                                     |
| composition, racine de composition | `composition`, composition root (`provideRoot`)       | The gathered contributions of a deliverable; the module that builds platform and extensions at startup.                   |
| coquille                           | `shell`                                               | The application frame: top bar, banners, dialog host, routed view, bottom bar.                                            |
| bandeau                            | `banner`                                              | A status strip under the top bar.                                                                                         |
| action de barre                    | toolbar action                                        | A button an extension adds to the top bar.                                                                                |
| livrable                           | `deliverable`                                         | A built product of this code: the static web version, the desktop application.                                            |
| démarrage                          | `startup` (`src/startup.ts`)                          | Starting the application. Distinct from bootstrap.                                                                        |
| amorçage                           | `bootstrap` (`BootstrapService`)                      | Creating the initial content of a new scoping repo.                                                                       |
| mentions légales                   | legal notice (`LegalNoticePage`, `DeliverableNotice`) | The legal-notice page; a deliverable adds its host, data and ownership phrases.                                           |
| aide (« Fonctionnement »)          | `help` (`HelpPage`, `HelpSection`)                    | The page explaining how the application works.                                                                            |
| réglages                           | `settings` (`SettingsPage`, `ProjectSettings`)        | What a project sets for itself in `ssk-canon.yml`.                                                                        |
| lien d'ouverture                   | deep link (`DeepLink`, `DEEP_LINK_SCHEME`)            | A `skanon:` / `web+canon:` link that opens a view of the application.                                                     |
| relève                             | handover                                              | The replacement of the former SSK Canon PWA by Skanon for users who had installed it (`tools/cutover/test-handover.mjs`). |
| bascule (outillage)                | cutover                                               | The migration from the former application, in `tools/cutover/`.                                                           |
| doublure                           | fake                                                  | A test double provided in place of a service.                                                                             |
